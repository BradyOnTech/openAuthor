# Desktop grouped update verification

PR [#23](https://github.com/BradyOnTech/openAuthor/pull/23), original head `5ec241173744c6a7fa0b68dd772cd8093c73f5ce`, is retained as an ancestor of the verified source `ee6958cd717467e1085222e4bbd7cfb92ad27624`. This packet covers Supabase 2.117.2, Vite 8.3.1, React plugin 6.1.1 and jsdom 30.1.1 on Node 24.19.0. It records local validation before root runs complete browser and native package acceptance against the frozen final branch.

The first normal desktop run passed 710/715. All five failures came from scene navigation accessibility queries. A focused run reproduced 5/6 failures in 683 ms. A DOM-only comparison showed jsdom 25 reporting an empty span display and `The Door DRA`; jsdom 30 reports `inline` and `The DoorDRA`. Chromium and WebKit also join the unstyled spans but separate them under the application's flex layout. Explicit scene button labels now preserve the visible title/status accessible name with either layout. All six existing navigation tests pass with their assertions unchanged; existing browser assertions, retries, timeouts and aggregate guards are unchanged.

jsdom 30 requires `^22.22.2 || ^24.15.0 || >=26.0.0`. Desktop and complete-E2E engine declarations, prerequisites and setup docs now state that range. The prerequisite command previously accepted the actual installed Node 22.17.0; it now rejects that version and accepts the supported Node 24.19.0. `.nvmrc` still selects current Node 22 for CI. [jsdom release notes](https://github.com/jsdom/jsdom/releases/tag/v30.0.0).

Vite 8 changes the default output target to Safari 16.4 and uses Rolldown/Oxc. The desktop still supports macOS 12, so the configuration explicitly retains the exact Vite 6 targets: ES2020, Edge 88, Firefox 78, Chrome 87 and Safari 14. Resolved JavaScript and CSS targets both match that list. The app uses plain `react()` without custom Babel transforms, so React plugin 6's Babel removal requires no additional plugin. All optional/native lock entries and libc metadata remain intact; only the root engine field differs from the original PR lock. [Vite 8 migration](https://v8.vite.dev/guide/migration), [React plugin changelog](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react/CHANGELOG.md).

Five persistent tests in `desktop/src/cloud/account.supabase.test.ts` now exercise the actual SDK, account wrapper, hashed asynchronous storage, WebCrypto ES256/JWKS verification, same-identity refresh/local sign-out and exact RPC transaction refusal. Held responses prove winning-session refresh recovery and the next RPC's exact bearer, cleared-storage refusal without RPC, wrong-device rejection and forged-signature rejection. Gates are released and pending operations settle before client disposal. An external resolver reran this exact immutable retained file with SDK 2.112.4: four tests passed and only winning-refresh recovery failed. SDK 2.117.2 passes all five, matching the upstream [refresh race fix](https://github.com/supabase/supabase-js/pull/2698/files). The earlier temporary Node-crypto probes and their one fixture parsing failure are separately identified in the independent review receipt.

Final normal validation passed 720/720 desktop tests across 94 files, TypeScript plus production Vite build, E2E type checking, repository integrity/audit, all five locked npm installs, peer validation and zero desktop audit vulnerabilities. Independent source reviews found no actionable regression. Build notices about existing large chunks and mixed static/dynamic contract imports remain non-failing.

The protocol tests use synthetic HTTP replies and an in-memory secret store; they do not certify live Supabase, native Keychain or actual cross-window events. Retaining old build targets does not certify execution on macOS 12. This packet does not certify the subsequent full browser aggregate, fresh ARM64/Intel package, signing/notarization or new-head hosted CI. Root retains separate frozen-head browser/package receipts; GitHub billing currently blocks new hosted jobs. Source and artifact hashes make these limits inspectable.
