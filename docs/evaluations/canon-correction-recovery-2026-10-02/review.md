# Canon assertion correction recovery

This is a bounded regression evaluation using an authored synthetic gate scene in a disposable book. No private author data or live provider calls were used. The fixture's prose remained unchanged. It verifies draft recovery and guarded saves; it does not evaluate the truth of the Canon assertion.

## Reproduction and diagnosis

The minimal rendered reproduction changed the accepted fact's Value from `blue` to `green`, unmounted the real `CanonFactCard`, then recreated it. The input returned to `blue` on two runs. A second red assertion confirmed that no original edit-version journal existed. The command was `cd desktop && npx vitest run src/components/editor/CanonFactCard.recovery.test.tsx`; [red.txt](red.txt) retains the failures.

The ranked hypotheses were (1) no durable journal, (2) opening overwrites a stored correction and (3) recovery key or validator rejection. The first was confirmed: the original editor held the correction and loaded fact solely in component-local state and never wrote recovery storage. The minimized case required only one changed field and the close/recreate boundary.

Independent review then identified a delayed-completion boundary: a newer authoritative fact could refresh the same mounted card before the older save response arrived. The rendered [delayed-completion red result](delayed-completion-red.txt) confirmed the older result was sent to the parent and its acknowledgement cleared the journal. Ranked hypotheses were (1) missing authoritative-version guard on completion, (2) unconditional recovery acknowledgement and (3) a parent-only merge race. The reproduction used a no-op parent callback, identifying the recovery acknowledgement as part of the defect. A further [shared-session red result](shared-session-red.txt) demonstrated that an unmounted editor's old props could downgrade a recovered session after a storage failure.

## Change and protections

The editor now uses the existing `useRecoverableDraft` module, keyed by book, actual Storyline and fact ID. Each edit journals the assertion fields with the loaded edit version. Recovered corrections open with a recovery notice. A fresh saved fact cannot silently replace the draft or advance its original precondition. If it changed, saving is blocked until the author either discards the correction or explicitly keeps it after comparing the saved fact with the recovered fields.

Cancel explicitly discards the scoped correction. Successful saves remove the journal only when the submitted correction is still the latest draft. A delayed completion preserves newer writing after the editor is reopened, and cannot update another Storyline's active editor. Guarded acknowledgements also refuse to downgrade a later authoritative snapshot or a newer journal baseline. The current mounted fact is checked before acknowledgement; unmounted props cannot replace the recovered session's authority. An older committed response retains the pending comparison rather than publishing its older fact. A refresh matching that exact committed result can still be acknowledged normally. Unreadable recovery records are retained and warned about rather than adopted; storage failures keep writing available within the running app and disclose that durable storage is unavailable.

## Verification and limits

- Focused rendered and recovery-helper tests: 25 passed across three files. They cover all assertion fields, original preconditions, stale review/discard, cancel, book/Storyline/fact isolation, failed saves, delayed completion after navigation and newer authoritative refresh, matching committed refresh, newer journal baselines, unreadable records and unavailable storage. See [focused.txt](focused.txt).
- TypeScript: `cd desktop && npx tsc --noEmit` passed after the parallel Memory scan changes stabilized.
- Real-core Chromium journey: one passed. The actual Memory workspace preserves value and evidence after navigation and page reload, blocks a recovered stale correction after an external guarded update, accepts it only after explicit review, clears saved/canceled journals, and leaves the manuscript unchanged. The same journey then holds delivery after a real core commit, updates the fact again through the core, refreshes the mounted card with Run Diagnostics and releases the older response; the fresh fact and original-version correction remain visible and saving is blocked. See [browser.txt](browser.txt), [recovered correction](recovered-canon-correction.png) and [stale comparison](stale-canon-correction.png).

The browser's native transport adapter runs the real Python core against a disposable book. The retained screenshots show the earlier passing recovery/stale-comparison flow; the final enhanced journey verifies the additional delayed-completion boundary through its assertions. Reload exercises persisted recovery without claiming a packaged-app force-quit test. Recovery is local to this device and does not survive a process restart when its storage is unavailable. The recovery helper gained an optional guarded acknowledgement; existing callers keep their interface. No API or core precondition change was required.
