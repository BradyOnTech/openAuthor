# Desktop preservation review — October 2

The Writing Voice workspace now lets an author add optional preservation instructions before requesting a preview. Each row records a supported kind and exact text. Empty rows, unsupported kinds, over-limit contracts and protected wording absent from the selected original prevent a preview request. The editable draft is separate from the immutable instructions shown with a saved comparison.

Preservation drafts use the existing local recovery journal, scoped to book, Storyline and scene. Saved comparisons show their exact original contract. Stage and refine requests send the saved comparison fingerprint; a later editable draft cannot replace it. Self-review distinguishes original and candidate quotations and continues to identify the generator as the reviewer. The core validates literal membership; these UI labels do not certify meaning or literary quality.

An explicit loaded-context boundary hides the previous workspace while a new book or Storyline loads. Preview, profile analysis, profile save and staged-proposal results check their submitted context before changing the visible workspace. Profile journal writes also check the loaded book/context, preventing an old dirty profile from being written under a new book. Unsaved profile drafts keep their original scope/version and remain available during book switches in the same mounted workspace even if local storage fails. Storage failure still prevents recovery after the entire workspace is closed; the existing warning asks the author to keep the screen open and save or copy the draft.

Refinement is keyed to book, Storyline, preview and direction. Late results after unmount cannot clear a reopened editor's feedback or invoke its callbacks. A result in the same mounted editor clears only the feedback it submitted; newer feedback remains available. Completed old results remain in core preview history for later review.
