# Reviewed Memory scan: CLI and desktop verification

The optional scan now has a separate **Review AI scan** action in the Memory suggestion Inbox. The author chooses at most six scenes and a configured provider/model, previews full exact saved sources plus the safe accepted identity projection, and explicitly sends that reviewed scope. Existing **Scan manuscript** stays available for local heuristic extraction. Candidates remain unconfirmed; uncertain entry types require **Correct → Entry type → Save correction** before Accept.

The public CLI adds `memory scan-preview --request-json` and `memory scan-ai --request-json`, using the same core configuration and fingerprint guards. Preview is read-only. Both desktop preview and Send wait for pending scene saves. Selection, model, provider configuration, project and Storyline changes invalidate the review; failed preview/Send retains the chosen scenes and removes Send until the author reviews again. An in-flight operation cannot be submitted twice or deliver an old result into a new project/Storyline.

The initial 1024×768 browser check reproduced a real layout defect: 30 scene choices pushed Close out of view. The repair gives the open review the Inbox's available height, bounds the picker, scrolls the review body, and keeps Preview/Send/Close in a footer. Inbox state and unfinished correction state remain in the parent; closing the review returns to the refreshed suggestions. The final browser check asserts scrollable picker/body and actions in the viewport both before preview and after six long source articles.

Verification uses only disposable original synthetic books and the local provider. Four public CLI tests, 21 rendered/provider/transport tests, TypeScript checking and one real-core browser journey passed. The browser starts with an empty queue, proves preview leaves it empty, then explicitly runs a reviewed local scan and verifies pending suggestions, no accepted entities or Canon Facts, and unchanged prose. It also verifies a changed source refuses the stale Send, chosen scene scope remains, Close is disabled while busy, and reopening requires a fresh preview. Busy handling uses a controlled browser transport pause, then releases the actual Python CLI once; this does not establish native cancellation support.

Red evidence is preserved separately: four CLI tests initially produced six failures including malformed-request subtests because the commands were absent; the API boundary test failed for the missing wrapper; the rendered module initially failed to import; the uncertain-type test failed because Accept was enabled; and the browser layout test failed because Close had viewport ratio zero. Final commands, counts and exact hashes are in `desktop-verification.json`. The three laptop screenshots show the first exact source including Chinese text, the last source's final line, and the stale-review warning.

The local path performs no semantic interpretation. Its identity refresh can span all saved scenes, while selected scenes limit fact and connection extraction; this is disclosed before Send. The semantic provider's language/type accuracy and author triage benefit remain unmeasured here. Exact quotations support review without proving an interpretation. The existing generic core-command API has no active cancellation handle, so the UI states that limitation and disables Close during submission. This evidence covers browser-to-real-core wiring, not signed native or physical-device release acceptance.

See `core-review.md` and `core-verification.json` for the separately verified core privacy, exact-evidence, ambiguity and locked mutation behavior. No external provider calls, author book data, deployment or Git metadata changes were used for this desktop verification.
